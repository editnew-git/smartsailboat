# Smart Sailboat publishing protocol

- Company: Smart Sailboat
- Company Code: `SSB`
- Destination: `https://smartsailboat.com`
- Public articles: `/stories/{permanent-slug}/`
- Audience: sailors, collaborators, partners, supporters and the public.

## Scope and topics

Publish approved project milestones, vessel stories, systems/equipment articles,
refit and maintenance stories, voyages, field tests and public lessons learned.
Approved documentary video may accompany a story through Pressly's media workflow.
Every article uses at least one canonical topic: `project-update`, `vessel-story`,
`systems`, `refit-maintenance`, `voyage`, or `safety-security`.

Use a practical, clear documentary voice. Explain what happened, the approved
context, work performed, lessons and next steps. Distinguish plans from results
and publication dates from event dates. Do not invent claims or completed work.

## Evidence and public boundaries

Business and vessel records remain in their owning systems. Use only a human-
supplied public brief or an authorized, selected public projection. Do not read
private vessel workspaces or publish raw transcripts, private inventories, serial
numbers, credentials, finances, contacts, live vessel locations, security layouts,
private findings, receipts, or unselected evidence.

Use attributable facts and approved photography. Preserve the supplied square
logo. The existing brand uses deep blue `#013650` and bright blue `#00A1DD`; the
website uses darker `#007BA8` for readable interactive text. Configure the saved
image profile explicitly before automatic branded covers are enabled. Generated
illustrations must be disclosed and cannot stand in for evidence of real work.

## Publishing

Apply Pressly's canonical Link Map and durable image workflow. Use the maintained
`video-embed` preview/apply command for YouTube players, preserving start times.
Do not use private Drive/Slack URLs, temporary URLs or invented iframe markup.

Search for an existing release before drafting and preserve its permanent ID and
slug when revising. Source intake authorizes private preparation only. Ordinary
articles need the current human publication instruction; video projects need the
original requester's trusted approval of the exact review package. Neither the
website nor this protocol grants automatic publication authority.

This fresh template does not define vessel-specific profile routes or migrate old
articles. Add such features deliberately when their public content is approved.
